# Repository Agent Instructions

## Start Here

Read the root `README.md`, then the relevant track's `README.md` and
`ROADMAP.md` before making changes.

## Roadmaps

- Treat roadmaps as self-directed research plans, not generated guides.
- Use `#`, `Topic`, and `Research target` columns.
- Include phase completion criteria and authoritative sources.
- Do not add status checkboxes, generated answers, or per-topic exercises.
- Keep language roadmaps focused on that language, runtime, standard library,
  tooling, and idioms.
- Put general algorithms, protocols, and system design in capstones or dedicated
  modules.
- Prefer specifications, official API documentation, standards, and primary
  project sources.
- Preserve configured language versions unless an upgrade is explicitly
  approved.

## Capstones

- Capstones are learner-owned implementation environments.
- They may evolve alongside roadmap research.
- Do not implement or substantially modify a capstone unless explicitly
  requested.
- Keep ownership, lifecycle, failure, concurrency, and verification expectations
  explicit.

## Changes

- Preserve unrelated worktree changes.
- Keep documentation concise and self-contained.
- Verify only what is proportional to the change.
- Obtain explicit approval before mutations, tests, builds, or external writes.
